# AGRILINK — FUNDAÇÃO DE DESIGN E EXPERIÊNCIA PRINCIPAL DO PRODUTO

## OBJETIVO

Reconstruir a fundação visual e de UX da AgriLink antes de expandir o redesign para o restante da plataforma.

Esta primeira fase deve estabelecer:

* linguagem visual definitiva
* padrões de interação
* arquitetura de navegação
* Design System
* componentes reutilizáveis
* experiência de onboarding
* dashboard
* marketplace

Essa fundação será posteriormente utilizada para reconstruir:

* Pedidos
* Negociações
* Logística
* Pagamentos
* Mensagens
* Notificações
* Experiência dos transportadores
* Administração
* Analytics

**NÃO redesenhar esses módulos profundamente nesta primeira fase.**

O objetivo é criar uma base de produto forte, proprietária e escalável.

O resultado NÃO pode parecer:

* um dashboard SaaS genérico
* uma aplicação criada pelo Lovable
* um template do v0
* um UI Kit de startup
* uma aplicação visualmente gerada por IA
* uma cópia de outro produto

A AgriLink deve parecer um produto maduro, criado por uma equipa profissional de Product Design, UX, UI e Engenharia de Software.

---

# 1. CONTEXTO DO PRODUTO

A AgriLink é uma plataforma AgriTech de marketplace e operações que conecta:

* Produtores
* Vendedores
* Compradores
* Transportadores

A plataforma permite:

* descobrir produtos agrícolas
* publicar produtos
* comparar preços
* fazer ofertas
* negociar
* criar pedidos
* organizar transporte
* realizar pagamentos
* acompanhar operações
* comunicar com outras partes da transação

A plataforma está inicialmente focada em Angola, mas deve possuir qualidade visual e estrutural suficiente para posteriormente crescer para outros mercados africanos e internacionais.

---

# 2. OBJETIVO DA EXPERIÊNCIA

A interface deve comunicar:

**TECNOLOGIA

* AGRICULTURA
* COMÉRCIO
* LOGÍSTICA
* CONFIANÇA
* CONTEXTO AFRICANO
* ESCALA**

A direção visual deve ser:

* premium
* moderna
* sofisticada
* futurista
* editorial
* operacional
* confiável
* altamente utilizável

Porém, NÃO deve ser:

* cyberpunk
* excessivamente futurista
* carregada de neon
* uma fintech genérica
* uma startup verde genérica
* excessivamente baseada em glassmorphism

O caráter futurista deve surgir principalmente através de:

* arquitetura da informação
* tipografia
* precisão visual
* interação
* movimento
* hierarquia
* utilização inteligente de dados

e NÃO através de:

* gradientes exagerados
* brilhos
* efeitos neon
* sombras excessivas
* elementos decorativos sem função

---

# 3. REGRA ABSOLUTA

## NÃO CRIAR UMA INTERFACE COM APARÊNCIA DE PRODUTO GERADO POR IA.

Evitar padrões previsíveis como:

* excesso de cards arredondados
* colocar cada seção dentro de um card
* sombras excessivas
* gradientes em excesso
* fundos verdes com gradiente
* glassmorphism em todos os elementos
* cards estatísticos idênticos
* enormes hero sections centralizadas
* excesso de pills
* excesso de badges
* blobs decorativos
* ilustrações SaaS genéricas
* utilização indiscriminada de ícones
* excesso de espaço vazio sem função
* layouts repetitivos de três colunas
* estética genérica de "startup de IA"
* cópia visual de Linear
* cópia visual de Stripe
* cópia visual de Notion
* cópia visual de Apple
* qualquer outra identidade visual reconhecível de terceiros

**Não copiar outras empresas.**

Estudar padrões de qualidade é aceitável.

Copiar identidade visual não é.

A AgriLink precisa possuir uma linguagem própria.

---

# 4. FILOSOFIA DE DESIGN

A experiência deve seguir esta prioridade:

**CLAREZA
→ VELOCIDADE
→ CONFIANÇA
→ OPERAÇÃO
→ QUALIDADE VISUAL**

Uma interface bonita que torna uma operação mais lenta é uma interface mal projetada.

Cada tela importante deve responder:

**O que o utilizador precisa compreender?**

**O que precisa fazer agora?**

**Qual informação é operacionalmente importante?**

**Qual é o próximo passo natural?**

---

# 5. ESCOPO DA PRIMEIRA FASE

Concentrar-se SOMENTE em:

### 1. Design System

### 2. Navegação

### 3. Onboarding

### 4. Dashboard

### 5. Marketplace

Não redesenhar profundamente neste momento:

* Pagamentos
* Logística
* Administração
* Mensagens
* Gestão avançada de pedidos

Entretanto, o Design System deve ser suficientemente sólido para que esses módulos possam ser construídos posteriormente sem alterar a linguagem visual principal.

# 6. DESIGN SYSTEM PRIMEIRO

Antes de construir as páginas, criar a fundação do Design System.

Não começar pelas telas.

Primeiro definir:

* tokens
* tipografia
* cores
* espaçamento
* raios
* bordas
* elevação
* ícones
* estados
* animações
* componentes

Depois utilizar essa fundação para construir as interfaces.

# 7. SISTEMA TIPOGRÁFICO

Criar uma hierarquia tipográfica completa:

* Display
* H1
* H2
* H3
* H4
* Body Large
* Body
* Body Small
* Caption
* Label
* Numeric

A tipografia deve transmitir:

* precisão
* confiança
* modernidade
* maturidade tecnológica

Dar atenção especial aos números porque a AgriLink trabalha constantemente com:

* preços
* valores em Kz
* quantidades
* quilogramas
* toneladas
* distâncias
* estatísticas
* transações

Os números precisam possuir excelente legibilidade.

---

# 8. SISTEMA DE CORES

Não utilizar simplesmente:

**verde + branco.**

Criar uma paleta completa.

## Cor Primária

Um verde agrícola sofisticado e proprietário.

Evitar o verde genérico utilizado em milhares de aplicações.

## Tons profundos

Inspirados em:

* solo
* floresta
* carvão
* infraestrutura
* matéria orgânica

## Cor de destaque

Uma cor de acento controlada para:

* ações principais
* oportunidades
* estados importantes
* destaques
* feedback positivo

## Cores semânticas

Criar:

* Success
* Warning
* Error
* Info

## Neutros

Criar uma escala completa de neutros.

A interface deve possuir:

### Light Mode

e

### Dark Mode

O Dark Mode deve ser desenhado intencionalmente.

Não simplesmente inverter as cores.

# 10. SISTEMA DE BORDER RADIUS

Não tornar tudo excessivamente arredondado.

Utilizar diferentes níveis de raio conforme a hierarquia:

* Inputs → moderado
* Cards → moderado
* Grandes superfícies → discreto
* Botões → controlado
* Mapas → mínimo quando apropriado

A interface deve parecer estruturada e profissional.

Não infantilizada.

---

# 11. SISTEMA DE ELEVAÇÃO

Evitar sombras pesadas.

Criar níveis:

* Level 0
* Level 1
* Level 2
* Level 3

* contraste
* bordas
* espaçamento
* hierarquia

antes de utilizar sombras.

# 12. ICONOGRAFIA

Criar uma linguagem de ícones consistente.

Os ícones devem:

* possuir espessura consistente
* possuir proporções semelhantes
* comunicar claramente
* ter função real
* evitar decoração desnecessária

Não colocar um ícone ao lado de cada texto apenas porque existe espaço disponível.

# 27. DASHBOARD

O Dashboard deve ser operacional.

A primeira pergunta que deve responder é:

**"O que precisa da minha atenção agora?"**

Não:

**"Quantas estatísticas podemos colocar na tela?"**

---

# 28. ESTRUTURA DO DASHBOARD

Começar com uma saudação contextual.

Exemplo:

**"Bom dia, Cláudio."**

Depois:

**"Você tem 3 operações que precisam da sua atenção."**

Em seguida:

### AÇÕES PENDENTES

Exemplos:

* 3 pedidos aguardando confirmação
* 2 ofertas recebidas
* 1 pagamento pendente

As ações devem ser clicáveis.

# 29. ATIVIDADE RECENTE

* Produto publicado
* Transporte iniciado

# 56. PRINCÍPIO FINAL DE DESIGN

Se um componente pode ser removido sem prejudicar a usabilidade, remover.

Se um card existe apenas porque "dashboards normalmente têm cards", remover.

Se um gradiente existe apenas para tornar a interface "futurista", remover.

Se uma animação existe apenas porque parece bonita, remover.

Se um componente melhora:

* compreensão
* velocidade
* confiança
* operação

mantê-lo.
